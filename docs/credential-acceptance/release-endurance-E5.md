空闲采样是50ms采样累计，不是某个请求连续空转时长；offer不是许可，也未逐样本证明绑定/健康/权限全部可执行。不能把这些秒数叫精确饥饿时间。SQL wall包含往返、锁等待和解码，非纯DB CPU时间；后台累计wall可能重叠，不可直接求CPU占比。

**C50仍有队列协议成本。** I3/I16分别15883/14598次WAIT，对应16939/15307次dispatch，接近每个工作先做一轮WAIT再获准。ADMITTED+WAIT的事务累计wall约为测量窗口的91.6%/90.6%；另有53.09/59.08秒后台SQL累计wall和约21万次advisory失败。不能将等待全归因于账号满额，也不能声称原fairness问题在所有负载已关闭。与早期E2生命周期失败不同，本轮可以推进并最终完成，但有效吞吐仍受重复登记/推进和串行处理约束。

**C200本轮没有数据库WAIT票据。** WAIT和后台推进SQL均0，约35k个成功准入事务的mean为16.81/17.31ms，累计wall约603.50/603.92秒，对应614.47/613.77秒测量窗口。这个累计量包含跨节点事务开始/提交的少量重叠，不能当精确advisory锁占用率；但与单主体串行准入成为吞吐约束一致。实际58.43/56.83次dispatch/s不是以p95倒数估算。call平均2.69/2.80秒，其中最后一次事务之前等待平均2.67/2.79秒，包含本地turn、跨节点失败事务及退避。不能称作纯连接池等待，也未删除该等待来宣称20ms达标。

C200普通池WaitCount全为0；生命周期保留池合计分别5048/5262次等待，累计21.28/22.86秒，但Heartbeat最大43.34/64.75ms、Finish最大147.31/97.34ms。用户容量锁语句平均7.79/7.96ms，取得用户锁后持锁下界平均8.05/8.37ms；提交平均0.225/0.232ms。候选实例锁查询平均0.782/0.892ms，ledger+quota查询平均0.810/0.824ms。主要成本不是提交或单独候选查询。锁阶段wall包含SQL往返；pg_stat_activity采样另存完整JSON，不用该wall冒充纯锁时间。

advisory尝试包含获准和失败：C200两组分别243643/241918次尝试，207738/207038次失败，有效准入/尝试仅14.74%/14.42%。固定5ms重试仍有放大；先前同二进制A/B/A试验的有界退避虽减少失败尝试，却恶化call尾部，因此没有作为产品默认。该取舍及两处SQL合并的受控短测见 [成本对照](release-admission-cost.md)。各SQL阶段在整个call中累计，不能把所有阶段均值相加当最后一次事务耗时。
