## Local behavior retained during conflict resolution

- **OAuth refresh:**
  - The local cross-instance refresh lock (`acquireCrossInstanceLock`, 90s
    lease) stays.
  - Upstream's OpenAI persistence budget is computed from that lease (90s −
    21s reserved) instead of upstream's tokenCache lock TTL.
  - Upstream's OpenAI CAS persistence path is adopted.
  - `maxTokenRefreshLockSafetyMargin` was restored.
  - Upstream lock-lease tests were rewritten for the local lock. The
    configurable short-lease test was dropped because the local lease is a fixed
    constant.
- **Gateway routes:**
  - Local moderated route registration stays.
  - `/v1` and Codex direct chains use `groupBodyLimit`, and the per-route
    `textBodyLimit` there was removed so the memory budget is not reserved twice.
  - Root text routes keep `textBodyLimit`, as upstream does.
  - `rejectConflictingFields` was inserted after `groupModelAllowlist` in every
    local inline chain.
- **Gateway handlers:**
  - `/v1/responses` on the Gateway handler keeps the validating image-intent
    check, because the local pre-forward read path does not guarantee prior JSON
    validation.
  - Messages sets the forward/response model context and also schedules by
    upstream's channel-mapped `routingModel`.
  - The WebSocket follow-up turn runs upstream's conflicting-field rejection
    before the local requested-model context.
  - The OpenAI→Responses Messages conversion keeps the local reasoning-content
    normalization and drops `responsesReq.Input` after marshal.
- **Prompt audit:** local `legacyProvided` handling stays. The outer
  `req.Clone()` calls were removed because `PromptService.Enqueue` now copies
  only after its scope check.
- **Request body limit:** local diagnostics stay, and the message comes from
  upstream's `pkghttputil.BodyTooLargeMessage`.
- **Account test:** the local model-aware prompt is kept on Anthropic and
  Bedrock payloads, with upstream's temperature rule.
  `buildBedrockTestPayloadWithPrompt` was added for this.
- **Admin wiring:** `NewAdminService` keeps the local `usageLogRepo` and gains
  upstream's `userPlatformQuotaRepo`. `wire` regeneration matches except for the
  two local `SetCodexClientConfigCache` calls.
- **Frontend:**
  - `AccountUsageCell` keeps the admin-settings store import and uses
    `buildAccountUsageRefreshKey`.
  - The new upstream Claude estimate tests sit next to the local OpenAI
    active-query test.
  - `AccountsView.lite` installs Pinia for the real usage cell.

## Fixes applied during the merge

- **Prompt audit capture:** upstream's new request-path scope check in
  `PromptService.Enqueue` returned early outside async mode and for out-of-scope
  groups. That would have silently dropped the local selected-user captures
  (which run even while auditing is off, in any group) and non-client captures.
  The check now reads the configuration once and returns early only where the
  local Enqueuer would skip too. Regression test:
  `TestPromptServiceEnqueueKeepsSelectedUserCaptureOutsideAuditScope`.
  The double configuration read also deadlocked upstream's
  `TestAsyncAuditOwnsCopyBeforeLegacyOrHandlerCanMutateInput`.
- **Privacy test:** the local OpenAI OAuth privacy test registers its account
  in the repository stub, because background OpenAI rotations now persist
  through the success CAS.
- **Conflicting-field route test:** upstream's source assertion was adapted to
  the local per-route root chains. It now also asserts that no chain reaches
  `compositeTarget` without `rejectConflictingFields`.
