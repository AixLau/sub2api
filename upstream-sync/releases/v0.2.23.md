- Previous selected upstream release: `v0.2.21` (`6dd5a045b62e27e5b5b139adef91a171097f639b`).
- Upstream commit: `2af3f1e1` (`v0.2.23` + VERSION sync, `upstream/main` on 2026-11-18).
- 219 upstream commits merged into the product branch (117 local-only commits retained).

Integrated the v0.2.22 and v0.2.23 upstream releases: GPT-6.2 Sol / Astra
models and Codex descriptors, GPT-6.2 Ultra Fast entitlements by Pro plan,
configurable channel Ultra Fast pricing (`channel_model_pricing.ultrafast_multiplier`),
forced Ultra Fast per group (`groups.force_openai_ultrafast`), per-user billing

snapshot load / DB fallback coalescing per bucket with a stale-grace window,
zero-copy request-body hot paths, OpenAI pre-output idle failover bounded by the
first-output switch budget, keepalive events forwarded directly before first
output, deferred flushing for native Chat Completions passthrough, upstream
price-factor billing on default prices, Anthropic compatibility routes enforcing
reasoning-effort policies, sticky-session writeback after client disconnects,
Codex fork prompt-cache keys, Gemini Vertex multi-region endpoints, Gemini 4
Hydrogen pricing, Grok media error fields and search-call handling, HTML
no-store cache headers, OpenAI quota refresh freshness (`usage.source`), and
the Go 1.27.4 toolchain.

`251_group_usage_rollup_nonblocking_build.sql` and
`252_channel_pricing_ultrafast_multiplier.sql` share the `251_` prefix with local

local file was renamed. Ent code was regenerated from the merged schema.

## Local behavior retained during conflict resolution

- Scheduler snapshot cache: upstream's per-bucket singleflight load, stale-grace
  background reload and last_used reuse are adopted, but account records are
  still loaded through the local Redis fingerprint script
  (`loadSnapshotMasters` / `metaMemo`), so unchanged records are not re-sent.
  Upstream's payload-equality master reuse was folded into it: a memoized master
  whose model-mapping pre-resolution is stale (`SharedSnapshotCurrent`) does not
  offer its fingerprint and is re-fetched. Tests assert EVALSHA instead of
  metadata MGET.
- API key quota settlement keeps billing soft-deleted keys by ID without marking
  them exhausted; the new batched lane uses the same shared SQL and also skips
  the exhausted flag for deleted keys.
- Billing: the no-resolver `CalculateCostUnified` path keeps the local
  Fast/priority multiplier override and explicit reasoning-effort multipliers,
  now priced at the request's `PricingAt` (GPT-6.2 Ultra Fast is time-dependent).
  OpenAI usage costing routes both group and non-group requests through it.
  `ChannelModelPricing` / `ModelPricing` keep `MaxReasoningEffortMultiplier`
  alongside upstream `UltrafastMultiplier(Override)`.
- Codex account identity: upstream's `clientSessionID` parameter was added to the
  local `...WithInput` variants; every call site passes both the header session
  and the staged pre-rewrite identity input. The session-id header still
  outranks `client_metadata.session_id` (docs/codex-session-fingerprint.md); the
  upstream fork test asserts that local projection.
- OpenAI usage refresh keeps the local single `queryUsage` path (spark/global
  windows, rate-limit recovery) and adopts upstream's `Source=active` /
  `quota_refresh_failed` freshness semantics.
- Gateway compat handlers keep the local pre-forward request read; upstream's
  reasoning-effort policy and committed-no-content sticky release were added.
- Anthropic stream prelude holdback, `DoOpsUpstream` wrappers, raw Chat
  Completions SSE framer, OpenAI explicit-refusal marking, client-message
  localization, local `UpstreamHeaders` omission in chat fallbacks, and the
  local `hasOpenAIResponsesNamespaceToolDeclaration` (top-level tools only) are
  unchanged.
- Index HTML: still never answers 304 for nonce-bearing HTML; it now sends
  upstream's full no-store header set.
- Frontend: user usage page keeps its single-column trend layout; endpoint
  distribution keeps `showCost` / `showStandardCost` / `fillHeight` and gains the
  upstream account-cost column; zh channel locale keeps local wording plus the
  new Ultra Fast label.

## Fixes applied during the merge

- Git applied upstream's six-column endpoint-stats scan to the local-only
  endpoint-path query; the endpoint query now scans `account_cost` and the path
  query selects it too.
- `wire_gen.go` re-adds `contentModerationService` and
  `openAIQuotaAutoResetService` next to the upstream billing lane provider.
- OpenAI first-output keepalive forwarding uses the local staged-output state.
- Upstream handler tests mount route metadata / moderation receipts required by
  the local pipeline, stub `GetUserAccountCooldowns`, expect localized client
  messages, and use a non-"processing failure" message where they test
  cross-account failover (the local policy retries that message on the same
  account).
- `TestCodexKeepaliveDoesNotMaskUpstreamTimeoutOrPreventFailover` now expects
  upstream's pre-output idle failover instead of a `stream_timeout` event.
- Restored the `monthly` window label in `CNProviderQuotaCell` (present at the
  v0.2.21 base, dropped locally while its locale keys remained).
- `wire` regenerated from the merged provider sets matches `wire_gen.go` except
  for the two local `SetCodexClientConfigCache` calls, which were kept.
