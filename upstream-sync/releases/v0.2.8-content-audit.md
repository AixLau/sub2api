# Upstream content-audit replacement

Source: `Wei-Shaw/sub2api` tag `v0.2.8`,
commit `fd80b08c90b55edcad5b00171b53f08721d30da1`.

## Implementation

The audit service, input extraction, keyword matching, email notifications,
TypeSafe client, repository, admin handler, API types and risk-control view
use upstream code. The local provider switcher and custom audit implementation
have been removed rather than retained behind an engine adapter.

OpenAI and TypeSafe have independent keys, URLs, models, proxies, timeouts,
retries and thresholds. TypeSafe uses the upstream 13-category rule set plus three product-specific Chinese rules and
only audits text. Audit metadata records the engine, actual returned model,
rule version and skipped-image count. TypeSafe scores require their own thresholds.

The local audit-specific request-memory budget, admission queue and image-audit
concurrency configuration have been removed. Request body limits now come from
the existing gateway body-size settings. Audit worker/queue bounds, key health,
input limits, timeouts and retries use the upstream implementation.

Gateway integration preserves HTTP, WebSocket, Anthropic-compatible and batch-image
routes. HTTP checks are reused within a request; WebSocket checks run for each
turn. Batch-image submissions pass every prompt and its references through the
upstream image-input format before billing or submission. The separate prompt-audit
module remains connected through the upstream coordinator interface.

## Database and configuration

`248_content_moderation_engine_meta.sql` adds the nullable `engine_meta` JSONB
column. Existing migration files and historical audit columns are not rewritten
or dropped. No database migration has been run against production in this change.

The local Zhipu provider, cyber/biosecurity extensions, structured candidate rules,
semantic review, manual review, decision/pass caches and outbox controls are no
longer part of the content-audit configuration. After deployment, open
**Security audit → Content audit → Moderation Settings**, select an engine,
configure its URL/model/keys and thresholds, test the keys and save. Enable
content auditing and choose observation or pre-blocking as needed.

This change is a code replacement. It does not deploy or modify server runtime
configuration.

## Extended TypeSafe rules

The TypeSafe rule set includes three additional Chinese checks: cybersecurity for actionable unauthorized cyber operations, cyber_abuse for network and platform abuse, and biochemistry for actionable pathogen, toxin, hazardous-chemical or bioweapon assistance. Defensive security research, public-health work, laboratory safety and other non-operational contexts are explicitly excluded by the prompts.
