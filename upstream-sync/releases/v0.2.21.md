## Migrations

Upstream `249_add_usage_logs_api_key_cost_index_notx.sql` and
`250_openai_cache_write_ttl.sql` share numeric prefixes with local
`249_usage_dashboard_user_daily.sql` / `250_usage_dashboard_user_daily_append.sql`.
The runner keys `schema_migrations` by full filename and sorts lexically, so
both sets apply (upstream files sort first within each prefix) and no local
file was renamed. Already-deployed local migrations keep their checksums.

## Local behavior retained during conflict resolution

- Usage log insert layout: the two new TTL columns were placed after
  `native_compaction_v2` and before `created_at`, keeping the local `source`
  column, `COALESCE(account_id, 0)` select, phase-latency columns and trailing
  `upstream_request_id` (70 insert args / 72 select columns). All five insert
  paths, the select list, the scanner and index-based tests were updated together.
- Ent generated code was regenerated from the merged schema rather than
  hand-merged.
- `ChannelModelPricing` keeps the local `MaxReasoningEffortMultiplier` alongside
  upstream `CacheWrite12hPrice`.
- `/v1/responses` UTF-8 validation lives in the local pre-forward read
  (`readOpenAIHTTPPreForwardRequest`) before compact normalization, so the
  pipeline remains the single body-read path; the handler-level copy was not
  duplicated. Upstream page-context normalization runs in the handler as upstream
  placed it.
- TTFT: upstream's shared `openAIStreamDataStartsTTFT` was re-expressed over the
  local semantic rule (`openAIStreamDataStartsFirstResponse`), so SSE and WS
  report on the same local basis; `openAITTFTMode` gained upstream's fallback to
  the cached gateway-forwarding settings.
- User purchase page keeps the local redesigned checkout (upstream's legacy
  template block dropped); upstream's 6-decimal formatter is used for the local
  1:1 configuration warning.
- Keys page combines the local first-key celebration logic with upstream's
  non-blocking usage-stat loading.
- Client-message localization stays; the upstream UTF-8 field-validation test
  asserts on the field name instead of the English sentence.
